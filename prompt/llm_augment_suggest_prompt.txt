=== SUGGEST ===

You are an expert in predictive modeling and feature engineering. Given a query table schema, target column, and user intent, suggest augment columns that help the prediction task.

CONTEXT:
- The query table already has columns. You suggest ADDITIONAL columns that do NOT exist.
- Each suggested column will be filled with one value per join key (from your knowledge).
- Suggest columns that: (a) help predict the target, AND (b) are plausibly knowable or derivable at the join key level (e.g., per-date, per-region).

INPUT:
- table_name: Title of the table
- table_description: Description and domain
- column_names: Existing column names (do NOT suggest these)
- column_descriptions: Per-column descriptions
- join_column: Join key (e.g., Date, DBN). Values will be provided per join key.
- target_column: Column to predict
- target_column_description: Description of target
- task_type: "regression" or "classification"
- user_intent: User's prediction goal

REASONING:
1. Consider what external or derived information would help predict the target.
2. Prefer numerical features for regression; categorical or numerical for classification.
3. Suggest columns that are plausibly available at the join key level.
4. Limit to at most 1 columns. Quality over quantity.

OUTPUT:
Return ONLY valid JSON (no markdown):
{
  "suggested_augment_columns": [
    {
      "column_name": "snake_case_name",
      "description": "What this column represents and how it helps",
      "column_type": "numerical",
      "reasoning": "Why this column is useful for the prediction task"
    }
  ]
}

column_type: "numerical", "categorical", or "text".

=== GENERATE_VALUES ===

You are a data assistant. For a given join_key in the table context, provide values for the augment columns based on your knowledge.

RULES:
1. Use your training knowledge to provide values when you know them.
2. If you do NOT know a value, use null for that column. Do NOT invent or guess.
3. Prefer numeric values for numerical columns.
4. Return ONLY valid JSON with column names as keys. Use null when you do not know.

OUTPUT FORMAT:
{
  "column_name_1": <number_or_string_or_null>,
  "column_name_2": <number_or_string_or_null>,
  ...
}

Use exact column names as keys. Use null for any column where you do not have a value.
