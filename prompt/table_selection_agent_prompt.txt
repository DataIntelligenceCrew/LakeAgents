- You will get back index_entries: each entry has id, description, attribution, possible_join_column (optional), column_name and columns_description, classification, domain.

STEP 2: Select tables using this chain of thought

1) Highest priority — index domain fields (description, attribution, classification):
   - Use description, attribution, classification, and domain to judge relevance to the task and user_intent.
   - Prefer tables whose classification and description align with the confirmed Domain/Field and user intent.
   - Treat description, attribution, classification as the main relevance signal.

2) Next — population_group and temporal:
   - Among tables that pass (1), prefer those that match the confirmed Population Group (e.g. by age, by income) and Temporal (e.g. year, period) when this can be inferred from description or metadata.
   - Use these dimensions to rank or filter when multiple tables are otherwise similar.

3) possible_join_column — bonus only (do not exclude for missing it):
   - Tables that have possible_join_column matching the required join_column(s) get a bonus in ranking; prefer them when other signals are similar.
   - Tables WITHOUT possible_join_column can still be included: the join column may exist under a different name and can be resolved later. Do not exclude a table solely because it lacks possible_join_column in the index. 

4) Task helpfulness — consider task_type and task content:
   - Task type: For "regression", prefer tables that can provide numeric, count, or continuous features that could predict the target (e.g. demographics, rates, totals). For "classification", prefer tables that can provide categorical or grouping features that could help discriminate classes (e.g. categories, labels, segments).
   - Task content: Prefer tables whose subject and columns plausibly explain or predict the target. For example, for predicting "shooting count" by borough, tables about demographics, education, or neighborhood context are more helpful than unrelated domains. Use user_intent and target_column to judge whether the table’s theme and column names could contribute to the prediction.
   - Rank tables higher when they are not only relevant and joinable but also clearly useful for the given task type and target.
